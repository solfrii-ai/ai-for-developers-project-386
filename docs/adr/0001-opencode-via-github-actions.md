# Интеграция OpenCode через GitHub Actions

**Статус:** accepted

## Решение

OpenCode используется в двух сценариях:

- `opencode` — ручное взаимодействие через команду `/opencode` в начале комментария. Workflow использует OIDC и GitHub App, поскольку агент может изменять код и создавать PR.
- `opencode-review` — автоматическое ревью, которое запускается только при переводе PR пользователем в `ready_for_review`. Этот и другие автоматические `opencode-*` workflow используют `GITHUB_TOKEN` с минимально необходимыми правами сценария.

**Общие инварианты:**

- Все workflow запускает только человек. Проверяется инициатор события, а не автор issue или PR: OpenCode не запускает сам себя, но PR бота можно ревьюить после подтверждения человеком.
- Фильтр события не заменяет проверку прав репозитория.
- Событие, которое не может запустить workflow, не должно отменять активный запуск. Если это нельзя гарантировать условиями отмены, автоматическая отмена отключается.
- Основная и small-модель: `opencode/deepseek-v4.1-flash`.

## Безопасность

Для `issue_comment` в `opencode.yml` принят риск `dangerous-triggers`, поскольку workflow получает OIDC-токен и доступ к API-ключу.
Проверка инициатора не устраняет prompt injection. Исключение пересматривается до **2027-02-15**, а также при изменении триггеров или аутентификации.

## Последствия

Новые коммиты после перевода PR в ready не запускают повторное ревью. Для повторного запуска PR нужно вернуть в draft и снова перевести в `ready_for_review`.
