# Интеграция OpenCode через GitHub Actions

**Статус:** accepted

## Контекст

OpenCode нужен для двух разных сценариев: ручной работы с агентом в issue и pull request и автоматического ревью готовых PR. Эти сценарии используют одну интеграцию, но имеют разные способы запуска и аутентификации.

## Решение

### `opencode`: ручное взаимодействие

- Агент запускается явной командой `/oc` или `/opencode` **в начале комментария** к issue, pull request или строкам кода в review.
- Запуск должен быть инициирован человеком. Боты, включая `opencode-agent[bot]`, не запускают workflow и не управляют активными запусками.
- Workflow использует OIDC и GitHub App `opencode-agent`, поскольку по команде пользователя агент может не только отвечать, но и изменять код, создавать ветки и PR.
- Новые комментарии не отменяют уже работающего агента: автоматическая отмена активного запуска отключена.

### `opencode-review`: ревью готового PR

- Ревью запускается только тогда, когда пользователь переводит PR в `ready_for_review`.
- Открытие, переоткрытие и добавление коммитов в PR сами по себе ревью не запускают. Draft PR не ревьюится.
- Автор PR может быть ботом, в том числе `opencode-agent[bot]`; важно, кто инициировал перевод в ready, а не кто создал PR.
- Workflow использует `GITHUB_TOKEN` с правами, необходимыми только для чтения контекста PR и публикации результата ревью.

Тот же принцип действует для будущих `opencode-*` workflow: автоматические сценарии используют `GITHUB_TOKEN`, тогда как интерактивный `opencode` остаётся на OIDC.

### Общие принципы

- OpenCode не должен запускать сам себя: инициатором любого OpenCode workflow должен быть пользователь, а не бот.
- Событие, которое не может запустить workflow, не должно отменять активный запуск. Условия автоматической отмены должны соответствовать условиям запуска; если безопасно выразить это нельзя, автоматическая отмена отключается.
- Запуск и управление запусками не должны быть доступны посторонним акторам; права репозитория проверяются дополнительно к фильтру события.
- Actions закрепляются полными commit SHA, API-ключи передаются через секреты, права токенов ограничиваются сценарием, а конкурирующие запуски и время работы ограничиваются через concurrency и timeout.
- Workflow проверяются командой `mise run check`.

## Модели

Во всех OpenCode workflow основная и small-модель совпадают: `opencode/deepseek-v4.1-flash`. Это исключает скрытое переключение между моделями для основного и вспомогательного контекста.

## Безопасность

`issue_comment` остаётся осознанным исключением правила `dangerous-triggers`: интерактивный workflow получает OIDC-токен и доступ к API-ключу. Явная команда и проверка типа актора уменьшают случайные запуски, но не устраняют prompt injection или компрометацию учётной записи.

Исключение допускается только непосредственно над `issue_comment` в `.github/workflows/opencode.yml`; глобальные подавления запрещены. Его нужно пересмотреть до **2027-02-15**, а также при изменении триггеров или схемы аутентификации.

## Последствия

- После перевода PR в ready новые коммиты не запускают повторное ревью. Для повторного запуска PR нужно вернуть в draft и снова перевести в `ready_for_review`.
- Команды в середине комментария не активируют ручной сценарий; команда должна быть первым содержимым комментария.
- Активная ручная сессия не прерывается новыми комментариями.
