# Технологический стек приложения

**Статус:** accepted

## Решение

Frontend и backend разрабатываются как отдельные TypeScript-приложения в pnpm workspace: React + Vite и Node.js + Express. Единый язык упрощает работу с контрактными типами, а workspace даёт общую установку зависимостей и lockfile без объединения приложений в единый runtime.

Для UI используются shadcn/ui и Tailwind CSS. Компоненты добавляются в исходный код frontend через shadcn CLI. Для их поиска и установки AI-ассистентами используется [shadcn MCP Server](https://ui.shadcn.com/docs/mcp); он нужен только при разработке и не входит в runtime приложения.

Предметное API описывается через TypeSpec и компилируется в OpenAPI. Спецификация используется для валидации Express (`express-openapi-validator`) и генерации типизированного frontend-клиента (`openapi-typescript` + `openapi-fetch`). Это уменьшает расхождение контракта и реализации.

TypeSpec, OpenAPI, валидация и генерация клиента подключаются начиная с первой предметной операции. Инфраструктурные проверки без предметных данных, такие как `GET /api/health`, реализуются напрямую в Express; frontend обращается к ним через встроенный `fetch`.

Для постоянного хранения используется PGLite, доступ осуществляется через Drizzle ORM с PostgreSQL-схемой (`pg-core`) и миграциями. PGLite не требует отдельного сервера, а PostgreSQL-диалект и изоляция подключения упрощают будущий переход на полноценный PostgreSQL: преимущественно меняется DB-адаптер, а схема и запросы сохраняются.

PGLite, Drizzle и миграции подключаются с первой операцией, которой необходимо сохранять состояние. До этого backend работает без БД.

Для дат используются нативные `Date` и `Intl.DateTimeFormat`, без Luxon. Все правила и отображение времени используют UTC: расписание владельца задано в UTC, календарные даты окна записи вычисляются по UTC, часовой пояс браузера не определяется и ручной выбор пояса отсутствует. В БД и API время хранится и передаётся в UTC. Суффикс UTC в интерфейсе не выводится. Единый пояс упрощает учебный проект ценой отказа от локального времени гостя и заменяет первоначальное правило Europe/Moscow. Логика времени изолируется в отдельном модуле.

Модульные и интеграционные тесты используют Vitest, сквозные пользовательские сценарии — Playwright.

## Конкурентность

PGLite использует одно эксклюзивное подключение и может скрывать гонки бронирования. Предварительной проверки доступности в приложении недостаточно: две параллельные транзакции на полноценном PostgreSQL могут одновременно увидеть свободный слот.

Проверка доступности и создание брони выполняются атомарно. Запрет пересекающихся интервалов дополнительно обеспечивается на уровне БД через PostgreSQL exclusion constraint. Обязателен интеграционный тест параллельных запросов, подтверждающий, что только одна конфликтующая бронь может быть создана.
